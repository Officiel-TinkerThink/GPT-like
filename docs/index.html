The model

The repository implements GPT-2 from scratch in PyTorch: token + position embeddings, a stack of pre-LayerNorm transformer blocks (causal multi-head attention, GELU feed-forward, residual connections) and an output head. The config file describes GPT-2 Small through XL (124 M – 1.5 B parameters).

For the browser, the same code was trained as a tiny GPT: context 64, embedding 192, 4 heads, 4 layers — 2.23 M parameters — on the 4,666 tokens of Edith Wharton's The Verdict, with the repo's word-level tokenizer. It is tiny enough to run at dozens of tokens per second in plain JavaScript, and the story is small enough that you can watch the model go from noise (epoch 1) to grammar (epoch 30) to memorisation (epoch 300).

What to notice

  • At high temperature the model stays on-topic but drifts; at temperature 0 it recites the story verbatim — the memorisation meter under the output shows how much of the text is copied.
  • Attention heads in a GPT are lower-triangular: a token can only attend to the past.
  • Validation loss stops improving long before training loss does — a 4,000-token dataset can't teach a language model much beyond itself.

Under the hood

  • tools/train_tiny.py trains with AdamW for 300 epochs and saves milestone checkpoints; tools/export_web.py quantises each to int8 (≈2.3 MB).
  • docs/js/gpt.js is the inference engine: the tokenizer, the forward pass with a KV cache, sampling identical to tools/infer.py (top-k, then temperature), and every head's attention weights.
  • Tests compare the JavaScript logits with PyTorch's for the reference prompt.

Fixes made along the way

  • TransformerBlock passed emb_dim as the attention mask's context length — it only worked when embeddings were at least as wide as the context.
  • The tokenizer's int_to_str was built from the wrong side of the vocabulary dict, so decode raised KeyError.
  • The hand-written GELU used 0.44715 instead of 0.044715.
  • tools/infer.py was empty; it now generates with temperature and top-k.
